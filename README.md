# Loan & Policy Assistant

A demonstration application that answers questions about fictional loan,
motor insurance, and customer support policies using retrieval-augmented
generation (RAG). A LangGraph workflow routes requests to policy retrieval,
a loan installment calculator, or both.

## Features

- Answers grounded in retrieved passages, with document and chunk citations.
- Three fictional policy documents indexed as seven chunks.
- Local 384-dimensional embeddings using Sentence-Transformers.
- Persistent Chroma vector database.
- Gemini-based request routing and policy answer generation.
- Fixed-rate installment calculations with input validation.
- Requests missing calculation inputs instead of assuming default values.
- FastAPI endpoints and interactive API documentation.
- Docker packaging with the embedding model and demo index bundled.
- Evaluation script that saves answers, human grades, routing results,
  and response timings.

## Technology

Python, LangChain Text Splitters, LangGraph, Google Gemini API,
Sentence-Transformers, Chroma, FastAPI, Pydantic, and Docker.

Embedding model: `sentence-transformers/all-MiniLM-L6-v2`

Generation model: `gemini-3.5-flash-lite`

## How it works

1. Gemini selects `policy`, `calculate`, or `both` and extracts calculation inputs.
2. Python validates the selected operation.
3. For policy requests, the question is embedded and the three nearest
   document chunks are retrieved from Chroma.
4. Gemini generates a policy answer using the retrieved evidence.
5. For calculation requests, Python validates inputs and computes payments.
6. The workflow combines the results.

Routing uses a JSON plan generated by the model. It does not currently use
Gemini's native function-calling interface.

The workflow calls the calculator as a local Python function.
The calculator is also independently accessible through an HTTP endpoint.

## API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Application startup status and indexed chunk count |
| POST | `/chat` | Run the policy and calculator workflow |
| POST | `/calculate` | Calculate installments without calling Gemini |

Example `/chat` request:

```json
{
  "question": "Does motor insurance cover mechanical breakdown?"
}
```

Example `/calculate` request:

```json
{
  "principal": 100000,
  "annual_rate_percent": 12,
  "months": 12
}
```

The calculator assumes a fixed nominal annual rate, monthly payments at
the end of each month, and no fees. Results are illustrative estimates,
not lender quotes or approval decisions.

## Run locally on Windows

Requires Python 3.13 and a Gemini API key with access to the configured model.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` locally and insert your own key.

```powershell
.\.venv\Scripts\python.exe ingest.py
.\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000/docs to test the API.

The first ingestion run downloads the embedding model.

## Run with Docker

Requires Docker running Linux containers.

Create `.env` from `.env.example` and add your key, then run:

```powershell
docker build -t loan-policy-assistant:local .
docker run --rm --name loan-policy-assistant --env-file .env -p 127.0.0.1:8000:8000 loan-policy-assistant:local
```

Open http://127.0.0.1:8000/docs.

The image includes the demo documents, embedding model, and generated index.
Rebuild the image after changing documents or application code.

The Gemini API key is supplied at runtime and is not included in the image.

## Evaluation

With the API running, execute in a separate terminal:

```powershell
.\.venv\Scripts\python.exe evaluate.py
```

The script checks routing automatically and asks a reviewer to grade
each answer against predefined criteria. Reports are saved in
`evaluation_results/`.

## Limitations

- Uses three small, fictional demonstration documents.
- No conversation memory; each question must include all required inputs.
- Model routing, input extraction, and generated citations can be incorrect.
- Prompt instructions reduce unsupported answers but do not guarantee prevention.
- One active chat request per application process.
- Gemini availability and rate limits affect response time and reliability.
- Response timing is recorded; token usage and cost monitoring are not implemented.
- No authentication, production deployment, or CI/CD pipeline is included.
- Dify integration and native model function calling are not implemented.
- Direct dependencies are pinned; indirect dependencies are not fully locked.

## Project files

- `agent.py`: LangGraph routing workflow.

- `evaluate.py`: repeatable evaluation and report saving.
